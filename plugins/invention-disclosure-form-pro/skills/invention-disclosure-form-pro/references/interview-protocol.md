# 사용자 인터뷰 프로토콜

발명 아이디어가 6개 항목을 모두 채우기에 부족할 때, 사용자에게 적절히 질문하여 보완 정보를 수집하는 가이드.

## 핵심 원칙

1. **AskUserQuestion 사용**: 자유 텍스트 질문 대신 선택지 + 자유응답 가능한 도구 활용
2. **한 라운드 최대 4개 질문**: 인지 부담 최소화. 4개 초과면 라운드를 나눔
3. **최대 2~3 라운드**: 무한 인터뷰는 사용자를 지치게 함. 핵심만 묻고 작성으로 진입
4. **추측 가능한 항목은 묻지 않음**: 본문에 단서가 있으면 그것을 활용
5. **선행 검색 우선**: 유사특허/배경문헌은 사용자에게 묻기 전 WebSearch로 후보를 마련해서 제시

## 항목별 질문 트리거

### 1. 발명 명칭

대부분 텍스트에서 추론 가능. 묻지 않고 후보 2~3개 만든 뒤 사용자 확인을 받는 편이 효율적.

질문 형식:
- "다음 중 어느 명칭이 가장 적합합니까?" + 후보 3개 + 자유 입력 옵션

### 2. 발명 배경

텍스트에 응용 맥락이 빠진 경우만 질문:
- "이 발명이 가장 우선적으로 적용되는 도메인은 무엇입니까?"
  - 의료 기기 / 산업 자동화 / 로보틱스 / 영상 처리 / 기타

### 2-(1) 유사특허 또는 출원

**먼저 WebSearch 시도**: 발명 키워드로 KIPRIS, Google Patents 검색 후 후보 3~5건을 사용자에게 제시.

질문 형식 (검색 후):
- "다음 후보 중 본 발명과 유사한 출원이 있다면 어느 것입니까? (복수 선택 가능)"

검색이 어렵거나 결과가 빈약하면:
- "이 발명과 유사한 기존 특허/출원을 알고 계십니까? (출원번호/등록번호와 명칭을 알려주세요)"
- 사용자가 모르면 "조사 필요" 표기로 처리 후 출원 전 KIPRIS 추가 검색을 안내

### 2-(2) 배경문헌 또는 관련특허

- "이 발명과 관련된 학술 논문, 제품, 또는 기술 자료가 있습니까?"
  - 옵션: 논문 / 상용 제품 / 둘 다 / 없음

### 2-(3) 본 연구원의 전출원

- "이 발명과 관련된 본인의 이전 출원이 있습니까? 출원번호 또는 등록번호를 알려주세요."
- 사용자가 "없음"이라고 답하면 본문에 "N/A"

### 3. 종래기술과 그 문제점

본문에 명시되지 않은 경우만:
- "이 발명이 대체하려는 가장 대표적인 종래 기술 1~2개는 무엇입니까?"
- "그 종래 기술의 핵심 문제점은 무엇입니까? (성능 한계 / 비용 / 복잡성 / 안전성 / 기타)"

### 4. 상세 설명 — 구성

가장 빈번하게 부족한 항목. **구체적 컴포넌트 분해를 유도**하는 질문이 핵심.

- "본 발명을 구성하는 주요 부품 또는 단계를 3~6개 항목으로 알려주세요. (각 항목 한 줄)"
- 알고리즘/소프트웨어 발명이라면:
  - "이 알고리즘의 처리 단계를 순서대로 알려주세요. 각 단계별로 입력/처리/출력이 명확하면 좋습니다."

### 4. 상세 설명 — 효과

- "이 발명이 실제 적용될 때 가장 큰 사용자 가치는 무엇입니까?"
  - 옵션: 비용 절감 / 정확도 개선 / 처리 속도 / 사용 편의성 / 안전성 / 기타

### 5. 보호받고 싶은 권리

본문이 충분하면 자동 추출 가능. 어려울 때만 질문:
- "이 발명에서 가장 중요하게 보호받고 싶은 핵심 아이디어 3~5개를 우선순위 순서로 알려주세요."

### 6. 추가자료

- "도면(모식도, 구성도, 흐름도)이 필요한 부분이 있습니까?"
  - 옵션: 시스템 구성도 / 알고리즘 흐름도 / 단면 모식도 / 실험 결과 그래프 / 도면 불필요

## AskUserQuestion 호출 예시

### 예시 1: 1라운드 통합 질문 (4개 묶음)

```python
AskUserQuestion(questions=[
  {
    "question": "이 발명의 주요 적용 도메인은 무엇입니까?",
    "header": "도메인",
    "multiSelect": False,
    "options": [
      {"label": "의료 기기", "description": "진단/치료/수술 보조 장비"},
      {"label": "산업 로봇", "description": "제조/검사/조립 자동화"},
      {"label": "소프트웨어/알고리즘", "description": "영상 처리, 기계학습 등"},
      {"label": "기타 기계 시스템", "description": "위 분류에 해당하지 않는 기계 발명"}
    ]
  },
  {
    "question": "유사특허/출원을 알고 계십니까?",
    "header": "유사특허",
    "multiSelect": False,
    "options": [
      {"label": "있음 - 직접 입력", "description": "출원번호와 명칭을 알고 있음"},
      {"label": "없음", "description": "조사된 바 없음"},
      {"label": "조사 필요", "description": "검색해서 찾아주기 바람"}
    ]
  },
  {
    "question": "본 연구원에서 본인이 출원한 관련 이전 특허가 있습니까?",
    "header": "전출원",
    "multiSelect": False,
    "options": [
      {"label": "있음", "description": "출원번호 또는 관리번호를 알고 있음"},
      {"label": "없음", "description": "관련 전출원 없음"}
    ]
  },
  {
    "question": "도면 생성이 필요합니까?",
    "header": "도면",
    "multiSelect": True,
    "options": [
      {"label": "시스템 구성도", "description": "전체 시스템 모듈/연결 관계"},
      {"label": "알고리즘 흐름도", "description": "처리 단계와 데이터 흐름"},
      {"label": "단면 모식도", "description": "물리적 구조의 단면/적층"},
      {"label": "도면 불필요", "description": "텍스트만으로 충분"}
    ]
  }
])
```

### 예시 2: 2라운드 — 구성 상세화

1라운드 답변 분석 후 구성 분해가 부족하다면:
- "본 발명의 핵심 컴포넌트(부품 또는 처리 단계) 3~6개를 한 줄씩 알려주세요." → 자유 텍스트로 받기

이 경우 AskUserQuestion 대신 일반 채팅 응답 요청이 더 자연스러움. 단일 자유 텍스트 입력은 AskUserQuestion 옵션 중 "Other"로 처리하거나, 그냥 텍스트 메시지로 묻고 사용자 응답을 기다림.

## 질문 생략 결정

다음 경우엔 질문하지 않는다:
- 항목 정보가 본문에 명시됨 (예: "이 발명은 의료 영상에서..." → 도메인 자명)
- 항목이 N/A로 적절함 (전출원 없음 등)
- 사용자가 명백히 작성을 빨리 끝내고 싶어함 (짧은 첫 입력 + "최대한 자동으로" 같은 신호)

질문하지 않은 항목은 합리적 기본값으로 채우거나 "사용자 보완 필요" 주석으로 표시하고 작성을 진행한다.
