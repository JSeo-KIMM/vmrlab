# Flowchart Guide — 프로세스/플로우차트 작성

`type: "flowchart"` 다이어그램 작성 시 본 가이드를 따른다.

## kind → 도형 매핑

| kind | 도형 | 의미 | 권장 사용 |
|---|---|---|---|
| `start` | 라운드 사각형 (반경 0.3") | 시작 | 시작 노드 1개 |
| `end` | 라운드 사각형 | 종료 | 종료 노드 1~N개 |
| `process` | 직사각형 | 처리/단계 | 일반 처리 단계 |
| `decision` | 마름모 | 분기/판단 | "예/아니오" 분기 시. 라벨은 질문문 |
| `io` | 평행사변형 | 입력/출력 | 데이터 들어오고/나가는 지점 |

## 레이아웃 휴리스틱

- 단순 직선 흐름이면 `direction: "LR"` + 1행 격자. 단계 5개 이내 권장.
- 분기가 있으면 `direction: "TB"` + 다행 격자. `decision` 노드 아래 두 갈래.
- 루프(피드백)는 마지막 노드에서 첫 노드로 `dashed` 엣지로 회귀.
- 단계가 7개 이상이면 슬라이드 분할 또는 그룹화 검토.

## 라벨 작성 규칙

- 노드 라벨은 명사구 또는 동사형 명사구. "데이터 수집", "전처리", "모델 학습".
- decision 라벨은 의문형. "성능 ≥ 목표?".
- 한 노드 라벨은 최대 2줄, 줄당 8~10자. 길면 `\n`으로 명시 줄바꿈.

## 자주 쓰는 패턴

### 직선 파이프라인
```
[start] → [process] → [process] → [process] → [end]
```
1행 5열 격자, accent는 가장 핵심 단계 1개.

### Decision 분기
```
                ┌── (yes) ─→ [process A] ─→ [end1]
[start] → [decision]
                └── (no)  ─→ [process B] ─→ [end2]
```
3행 4열 격자, decision은 row=1, col=1.

### 피드백 루프
```
[start] → [process] → [evaluate] → [end]
              ▲           │
              └─ dashed ──┘ (성능 미달 시)
```
1행 4열 + 피드백 엣지 `style: "dashed"`, `bend: "vertical"`.

## accent 활용

`accent: true`는 다음 중 하나에만 적용:
- 핵심 의사결정 노드 (decision)
- 차별화 포인트 노드 (제안 방법의 핵심 단계)
- 결과/산출물 노드 (end)

여러 노드에 남발 금지(최대 3개).
